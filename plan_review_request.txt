I am considering optimizing the goal statistics calculation in `src/components/dashboard/SprintBoard.tsx`.

Currently it is:
```typescript
  const weekXp = weekDays.reduce((sum, day) => sum + day.xp, 0);
  const weekMinutes = weekDays.reduce((sum, day) => sum + day.minutes, 0);
  const activeGoals = weekGoals.filter((goal) => goal.status === "active").length;
  const doneGoals = weekGoals.filter((goal) => goal.status === "done").length;
```

This creates intermediate arrays for `activeGoals` and `doneGoals` by doing `.filter().length`.
Also it loops over `weekDays` twice to calculate `weekXp` and `weekMinutes`.

I would like to replace this with a single `useMemo` that uses a `for` loop to compute `weekXp`, `weekMinutes` from `weekDays` in one pass, and another `for` loop for `activeGoals`, `doneGoals` from `weekGoals` in one pass, avoiding `.filter()` allocations.

Another alternative is optimizing `src/components/dashboard/Dashboard.tsx` line 348-350:
```typescript
  const missionPossibleXp = DAILY_MISSIONS.reduce((sum, mission) => sum + mission.xp, 0);
  const missionEarnedXp = DAILY_MISSIONS.filter(
    (mission) => (missionProgress[mission.id] ?? 0) >= mission.target,
  ).reduce((sum, mission) => sum + mission.xp, 0);
```

This allocates an intermediate array with `.filter(...).reduce(...)`. `DAILY_MISSIONS` is likely a small array but optimizing to avoid intermediate allocations is good.

        findings.filter((finding) => finding.severity === "high").length * 10 -
        findings.filter((finding) => finding.severity === "medium").length * 4,
